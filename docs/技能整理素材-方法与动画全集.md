## §1 立项提问阶段（grilling）

### 规则
需求存在任何未经证实的假设时，禁止写代码。把待定决策画成树，每轮只问前置条件已确定的；**每个问题必须附推荐答案 + 理由**，让用户能直接说 yes；能自己查证的（读文件、跑命令）不要问用户。

### 必问清单（本案例 11 问，按依赖顺序）
1. 主题具体是什么（分子/基因/影像/临床/科普）
2. 给谁看（决定术语密度与容错度）——**注意「评分人视角」是隐性需求，要主动挖**
3. 打开页面第一眼要让人看懂什么（一句话定调，给出「数字冲击型/提问互动型/反差悬念型」等候选）
4. 数据来源：真实可溯源 / 教学示意 / 混合
5. 视觉基调：深色沉浸 / 浅色专业 / 高对比
6. 交付形态：单页 landing / 多章节长滚动 / 多页
7. 要不要 3D（收益 vs 验收成本）
8. 互动增强：长舞台 / 鼠标跟随 / 第三方动画组件
9. 项目目录位置
10. 用户提供的参考材料如何落地（源码集成 vs 只当视觉参考）
11. 在线地址 / 部署方式

### 实战教训
- 用户在第二轮补充「**UI 好看是最重要的（老师评分）**」——这条隐含需求直接改变了后续所有风险取舍（宁用稳方案不炫技）。
- 用户中途修订决策（浅色 → 双主题）是正常的，决策表要记录「原决策作废」。

## §2 七阶段流程（核心方法论）

### 阶段 1：先问，不许猜
见 §1。边界清空之前不动手。

### 阶段 2：出计划，等审核
计划必须包含：
- **现状分析**（改现有项目每句话带 file:line；新建项目列文件清单）
- **决策表 D1-Dn**，每条写「为什么这么选」
- **分批次**，每批独立可部署、可回滚
- **验收标准必须脚本能判定**——「不卡顿」「观感好」是禁语
- 明确「不做什么」
- 计划写成 `docs/plan-<主题>.md` 入库

### 阶段 3：等明确确认
「嗯」「好」「行」视为含糊，再确认一次；「看着办」不算确认。

### 阶段 4：独立审核
派**全新上下文的子代理**审核计划。审核 prompt 模板（实战验证有效）：

```
你正在审核一份尚未开始实施的计划。你的任务是找出问题，不是批准。

## 必读
- 计划文档：<路径>
- 真实代码：<项目根>，重点 <文件>
- 验收工具：<脚本路径>

## 按优先级检查
1. 事实准确性（最高价值）：每一处 file:line 是否正确？每条关于现有行为的论断是否成立？错了的引用真实代码行反驳。
2. 完整性：声称实现 N 个决策，逐个检查是否都有任务落实。
3. 内部矛盾：A 节承诺的，B 节是否禁止了？
4. 具体技术风险：列出 3-5 个本任务最可能出错的点。
5. 遗漏：计划没写、实施者必须自己发明的东西有哪些？
6. 验收可检验性：每条标准能否被客观判断？哪些是模糊话？
7. 批次顺序：有没有批次依赖后面的批次？有没有东西不属于任何批次？

## 输出
编号列表，每条：严重程度（BLOCKING/MAJOR/MINOR）、位置、错在哪（带证据）、怎么修。
最后给结论：能否进入实施？
不要修改任何文件。不要为了礼貌而批准——什么都没找到的审核是失败的审核。
```

实战结果：一轮审核抓出 7 MAJOR + 9 MINOR，其中 3 条属于「验收机制本身失效」。

### 阶段 5：审核意见必须自己核实
**子代理会犯错**。逐条去代码里验证，确认成立才改。预设「预期有一条是它自己错的」。实战中 16 条全部成立（一次），另一次审核中它把 A 组件的属性安到 B 组件头上（idle 判定张冠李戴），靠读源码行号识破。

### 阶段 6：实测校正
审核代理靠读代码推断，**读不出运行时尺寸/帧率/合成行为**。用无头浏览器量：
- 元素实际 getBoundingClientRect
- 滚动到底的真实位移
- canvas 像素采样 / 截图亮度统计
- rAF 帧间隔分布

**所有写进文档的数字必须是实测值。**

### 阶段 7：分批实施
每批结束：跑完整验收 → git tag → 提交。提交信息写清「改了什么、为什么、实测数据」。
汇报固定三段：**做了什么（文件清单+实测数据）/ 还差什么 / 发现了什么（计划错还是代码错）**。

## §3 实测工具链（verify.mjs 骨架）

### 技术选型
- puppeteer-core + 系统 Chrome（不下载浏览器）
- 走 vite preview `--host 0.0.0.0`（默认只听 IPv6，127.0.0.1 连不上）
- Windows 构建前设 `TEMP/TMP` 到项目内目录（esbuild 临时目录随机 Access denied）

### 关键测量技术（全部实战验证）
| 测什么 | 怎么测 |
|---|---|
| 主题是否生效 | `document.documentElement.dataset.theme` + body 计算背景色 |
| 对比度 | 取元素 computed color，向上遍历找首个非透明背景，WCAG 公式计算 |
| 横向溢出 | `scrollWidth ≤ clientWidth + 1`，多视口（1280/768/375）× 多主题 |
| canvas 有内容 | **CDP 截图 → 页内 Image 解码 → 逐像素与背景差值计数**（WebGL canvas 未开 preserveDrawingBuffer 时 readPixels/toDataURL 只会读到空缓冲！） |
| 2D canvas 是否在动/停帧 | `toDataURL()` 前后两次比对（指针在场应不同；离开后 1.6s 应相同） |
| 帧率 | 页面注入 rAF 采集环收集 timestamp；CDP 鼠标沿利萨茹轨迹移动 10s；弃前 1s 热身取中位数 ≤33ms |
| 滚动进度条 | 读 computed transform 矩阵的 scaleX |
| hover 效果 | **本环境截图管线不捕获 DOM 重绘（内联改红背景 diff=0），改用 computed style 断言**（transform/opacity/blend/filter）+ 截图亮度界限（防黑块） |
| 触摸/降级模拟 | **必须独立浏览器进程**（CDP setTouchEmulationEnabled 关不掉；emulateMediaFeatures 用于 reduced-motion 安全） |
| 主题切换持久化 | 不能在注入过 evaluateOnNewDocument 的页面 reload（会再次注入覆盖），用**新开页面**验证 |
| 主题切换后真实像素 | 点击开关后量 hero 背景 + canvas 字形明暗主导（防止「CSS 对了渲染没跟上」的假绿） |
| ScrollTrigger pin | 滚到行程中段量 section rect.top ≈ 预期 pinTop；暴露 `window.__stage()` 验收钩子返回 pinCount/travel/trackX |
| travel 合成 | `travel == 自合成轨道宽 - 裁剪窗宽` 差值 ≤1px @两个视口 |

### 截图坐标陷阱
`elementHandle.boundingBox()` 是**视口坐标**；`page.screenshot({clip})` 是**页面坐标**。页内滚动后必须 `clip.y += scrollY`。（此坑在实战中造成 3 条断言假 FAIL。）

### 视口切换陷阱（后补，实测）
`page.setViewport(375)` 后立刻读 `scrollWidth` 会拿到缩窄前的旧值（`clientWidth` 已 375、`scrollWidth` 仍 1280），断言偶发 FAIL。setViewport 只保证视口已提交，不保证 reflow 完成；ScrollTrigger 的 pinSpacer 还要重算。封装 `setViewportSettled()`：等两次 rAF + 400ms + 轮询到 `{sw,cw}` 连续两次相同且 `cw === width`。**这类偶发问题重复跑才暴露，单次全绿不能当证据。**

### 截图管线局限
本环境（headless Chrome）**截图只捕获 canvas 纹理更新，不捕获 DOM 重绘**（内联改红背景 diff=0，真实 GPU/DPR 抖动/fullPage 全试过）。DOM 类视觉断言改用 computed style + 亮度界限组合。

## §4 实测坑全集（每条：现象→根因→修复→通用规则）

### 布局类
1. **全宽层不能用 100vw**：100vw 含滚动条宽，四写法三溢出 8px。唯一零溢出：`width: calc(100vw - var(--sbw)); left: 50%; translateX(-50%)`，`--sbw` 由 JS 写真实滚动条宽。**但若元素在 body 直下（未套限宽容器），width:100% 即 clientWidth，无需此 hack。**
2. **--sbw 不能只算一次**：滚动条出现（~310ms）不触发 resize 事件，挂载时算出来是 0。必须 `ResizeObserver` 观察 `document.documentElement`。
3. **scrollWidth 不含尾部 padding**：横向轨道宽度必须自行合成：`Σ card.offsetWidth + gap×(n-1) + paddingLeft + paddingRight`。
4. **pin 起点必须让出固定导航**：`start: 'top 68px'`（导航 64px 含边框，留 4px 间隙）。实测 pinTop 精确钉住。
5. **flex 属性对 absolute 包裹层的子元素无效**：内容层被 absolute 容器包裹时，给它 flex:1 不生效，会塌成内容高度导致标题被导航裁切。**修复：恢复 height:100%（父链都是 100%）**。→ 通用规则：改布局容器时检查每层的定位方式。
6. **绝对定位层不参与 flex 布局**：flex 容器里唯一的流内子项会被放到顶部——需要 `margin-top: auto` 压底。
7. **scroll-behavior:smooth 让脚本内所有 scrollIntoView/scrollTo 变异步**：程序化滚动必须 `behavior:'instant'`，否则 500ms 等待后坐标仍错位、hover 落空、elementFromPoint 返回 none。

### 构建类
8. **vitest 全绿 ≠ 能构建**：esbuild 剥类型。验收以 `npm run build` 为准。
9. **Windows esbuild 临时目录随机失败**：`TEMP/TMP` 设到项目内目录。
10. **Vite preview 默认只听 IPv6**：加 `--host 0.0.0.0`。
11. **从 markdown 提取代码时，结尾的 ``` 围栏会污染 CSS**：CSS 解析器把「围栏+后续选择器」整段当无效规则丢弃（.theme-switch 规则丢失→开关 0×0 不可点）。**提取后必须检查围栏残留与括号平衡。**
12. **React 18 StrictMode 双挂载是第三方 canvas 组件的毒药**：双挂载复用同一 canvas DOM 节点；若 cleanup 调 `WEBGL_lose_context.loseContext()`，重挂载的 getContext 拿回**同一个已死 context**，初始化中断、ResizeObserver 没挂、画布缓冲不随 resize 更新，且死 canvas 被 Chrome 合成为**不透明白色块**。修复：cleanup 移除 loseContext（canvas 随卸载由浏览器回收）。**只在 dev 出现，生产构建正常——极易漏测。**
13. **第三方开关组件的 label 转发点击在 React 受控下有竞态**：checkbox `display:none` + label 转发，在主线程被动画占满时会双触发/丢失。修复：checkbox 改 `position:absolute; inset:0; opacity:0` 透明覆盖层直击 input；hover 微交互改由根节点 `:hover` 驱动。

### 交互与无障碍类
14. **mix-blend-mode: screen 在浅色背景上等于不可见**：深色主题用 screen 加光，浅色主题换 multiply 或低透明色斑——**做成 CSS 变量随主题切换**（`--glow-blend`）。
15. **CSS 优先级：裸类名被父级选择器压过**：`.topnav a` (0,1,1) 压过 `.topnav__github` (0,1,0)。导航内一律 `.topnav .topnav__xxx`。
16. **滚动条出现不触发 resize**：--sbw 之类依赖视口宽的值用 ResizeObserver 观察 documentElement 盒模型。
17. **ScrollTrigger `end:'max'` 缓存文档高度**：字体加载后页面变长，进度条系统性偏高。修：`fonts.ready` 和 `load` 各 `ScrollTrigger.refresh()`。或进度条不用 ScrollTrigger（scroll+rAF 计算）。
18. **React 受控 input 不能直接赋 .value**：`Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set.call(input,'100')` + dispatchEvent。
19. **CDP 触摸模拟开了关不掉**：触摸断言独立浏览器进程。
20. **同 URL goto 会恢复滚动位置**：需要「顶部状态」的断言显式 `scrollTo(0,0)`。
21. **setViewport 后布局是异步的**：见 §3「视口切换陷阱」。这是唯一一个「单次跑全绿也证明不了」的坑，验收脚本必须重复跑。

## §5 动画/交互效果实现细节

### 5.1 TechText 标题（canvas 逐字网格）
- **效果**：文字以虚线网格字形渲染，指针移动处出现透镜揭示（字形实心化），可拖拽、松手回弹。
- **源码**：React Bits TechText（2D canvas，约 990 行）。**关键机制**：字形预渲染成离屏 canvas sprite，缓存键 = `[text, font, size, letterSpacing, align, ink, dash..., width, height, dpr].join('|')`——**含 ink 色值，主题切换自动重建**。
- **集成改动**（4 处以内）：容器色 `color: var(--ink)`（canvas 取 `getComputedStyle(container).color`，且内部 MutationObserver 监听 documentElement 的 data-theme/class/style 变化 wake 重绘）；`sweep={false}`；中文副标不进 canvas（CJK 字形测量未验证，走 DOM）；字体栈由容器 CSS 提供（未传 fontFamily 时走 computed）。
- **停帧机制**：`sweep=false` 时 `active = pointer.inside || dragging`；指针离开 → settling 收敛 → rAF 停、画面冻结；pointerenter 唤醒。**无需注入代码**。
- **验收**：canvas toDataURL 双采样（在场时不同=在动；离开 1.6s 后相同=停帧）。

### 5.2 SwarmCursor 粒子群（WebGL2 流体）
- **效果**：数百粒子组成流体跟随指针漫游（idle='roam' 时无指针也自主游走），点击爆散（burst），进场聚拢（intro）。
- **源码**：React Bits SwarmCursor（WebGL2，945 行）。每帧 2 次半拉格朗日平流 + 12 步压力求解；`blendFunc(ONE, ONE_MINUS_SRC_ALPHA)` + `premultipliedAlpha: true`。
- **集成改动**（3 处）：① `lightMode`/`color`/`accentColor` 从 CSS 变量读（WebGL 需具体色值，`getComputedStyle(documentElement).getPropertyValue('--ink')`，useMemo 依赖 theme）；② `<768px` 与 reduced-motion 条件挂载（matchMedia 监听）；③ **cleanup 移除 `loseContext()`**（§4-12）。
- **层叠**：TechText 作为 SwarmCursor 的 **children**——canvas `absolute inset:0` 在内容层之下，`pointer-events:none` 不拦截。
- **性能实测**：hero 双 canvas 同屏，rAF 帧间隔中位 16.7ms（60fps 满帧）。
- **降级**：<768px 与 reduced-motion 不挂载；IntersectionObserver 离屏自动停帧。

### 5.3 长舞台横向滚动（GSAP ScrollTrigger）
- **结构**：`.stage-pin`（全宽氛围背景，被 pin）→ `.stage-window`（max-width 1180，overflow hidden）→ `.stage-track`（flex，卡片 `flex: 0 0 380px`，width: max-content）。
- **参数**：pin 起点 `'top 68px'`；行程 = 自合成位移 × **3.5**（1 倍会一闪而过被当成卡顿）；`scrub: 1`（平滑追赶）；`invalidateOnRefresh: true`；`anticipatePin: 1`。
- **轨道宽度自合成**（不用 scrollWidth，少尾部 padding）：
  ```js
  const cards = track.querySelectorAll('.station');
  let w = 0; cards.forEach(c => w += c.offsetWidth);
  const cs = getComputedStyle(track);
  w += (parseFloat(cs.columnGap)||0) * (cards.length-1) + (parseFloat(cs.paddingLeft)||0) + (parseFloat(cs.paddingRight)||0);
  ```
- **gsap.matchMedia 分支**：`(min-width: 768px) and (prefers-reduced-motion: no-preference)` 内才建 pin；分支 cleanup 自动删验收钩子。
- **验收钩子**：`window.__stage = () => ({pinCount, travel, trackW, winW, sectionTop, trackX})`。
- **实测**：pinTop 精确 68.0；travel 合成偏差 0.0px @1280/1440；<768px pin=0 轨道 column；reduced-motion pin=0。

### 5.4 SVG 曲线随滚动描画（DrawSVG 免费替代）
```js
const len = path.getTotalLength();
path.style.strokeDasharray = `${len}`; path.style.strokeDashoffset = `${len}`;
gsap.timeline({scrollTrigger:{...}}).to(path, {strokeDashoffset: 0, ease:'none'}, 0);
```
与轨道位移共用同一 ScrollTrigger 时间线。配 `role="img"` + 描述性 aria-label。

### 5.5 双主题系统
- `<html data-theme="light|dark">` + tokens.css 两套变量；**index.html 内联脚本首帧前定主题**（localStorage → prefers-color-scheme → light），防闪白。
- ThemeProvider：state → useEffect 写 dataset + localStorage。
- **坑**：子组件 render 早于父组件 useEffect——**render 期间 getComputedStyle 读到的是旧主题值**，依赖主题的具体色值（如传给 WebGL 的）要在 effects 后的重渲里取，或接受一帧延迟。
- 数据编码色独立 `:root` 块不随主题（Okabe-Ito 色盲友好色板，黑省略因深底不可见）；verify 断言两主题取值相同。

### 5.6 主题切换开关（第三方 CSS 改造流程）
外部片段（uiverse 等）五步处理：硬编码色→CSS 变量；组件级尺寸可留但实测最小视口；**选择器笔误实测确认**（nth-last-of-type(3) 在 3 个同类元素时匹配第 1 个——可能是原设计而非 bug）；无限动画加 reduced-motion 兜底；渲染实测后再入库。
React 受控竞态修复：checkbox 从 display:none+label 转发改成**透明覆盖层直击 input**（absolute inset:0 opacity:0 z 顶层）。

### 5.7 卡片发光 + blur 组
- 描边用**两层元素法**（.edge 渐变实心层 z1 + .body surface 层内缩 1px z2），**禁用 mask-composite（整卡变黑）与 border-image（丢圆角）**。
- 光晕：radial-gradient 层 `mix-blend-mode: var(--glow-blend)`，hover opacity 0→1。
- blur 组：`.group:has(.card:hover) .card:not(:hover) { filter: blur(3px) saturate(.9); opacity: .55 }`。
- hover 上浮 `translateY(-4px)`；全部走 opacity/transform/filter（合成器路径，不触发重排）。

### 5.8 进度条
scroll + rAF 节流（不用 ScrollTrigger，规避 end:'max' 缓存），`scaleX` 驱动，贴导航下缘或视口最上缘。

### 5.9 递质下落 / 循环小动画
CSS keyframes + nth-of-type stagger 延迟；base.css 全局 `@media (prefers-reduced-motion: reduce) { * { animation-duration: .01ms !important; transition-duration: .01ms !important } }` 兜底（信息不减，只停动）。

### 5.10 平滑滚动与锚点
`html { scroll-behavior: smooth; scroll-padding-top: 84px }`；reduced-motion 下 scroll-behavior: auto；**程序化滚动（脚本/JS）一律 behavior:'instant'**。

## §6 无障碍与响应式规范

- 每个可视化容器：`data-viz` + `role="img"` + 描述性 `aria-label`（verify 断言非空）
- 对比度：正文 ≥4.5、大字 ≥3.0，**两主题各算一遍**
- `prefers-reduced-motion`：动效全停、**信息一条不少**（断言章节文本量不减）
- <768px：长舞台竖排静态 + IntersectionObserver 单次淡入；重粒子层不挂载
- 触摸断言独立浏览器进程（CDP 触摸模拟不可逆）

## §7 科普/医学内容规范（数据出处系统）

- 全站数字集中 `src/data/sources.ts`，TS 类型强制 `source` 字段：`kind: 'literature' | 'illustrative'`
- vitest 校验：字段非空、id 无重复、两类必须同时存在（诚实性底线）
- 页面组件从注册表取数（`getFact(id)`），不散落硬编码
- 出处展示方式按用户偏好可调（本案例：行内删除，集中到文末「参考资料」区块，文献给全引用、示意标「教学示意（理由）」）
- 没有单篇文献能背书的通行值（如「7000 突触」）**老实降级为教学示意**，不假装有出处
- 边界声明（是什么/不是什么/非医疗建议）放显眼位置

## §8 交付与部署

- git 分批 tag；每批 commit 信息含「改了什么/为什么/实测数据」
